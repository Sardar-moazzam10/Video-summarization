ABSTRACT

VidFusion is a full-stack web platform that turns one or more long YouTube videos into a short, faithful summary: a condensed highlight-reel video cut with the original audio, and a structured written summary with chapters, key takeaways, and notable quotes. A user searches for or pastes one to ten YouTube videos, picks a target duration from six duration profiles (2 to 30 minutes), and the system downloads and transcribes the source material, semantically segments it into complete-thought units, extracts the concepts the content is actually about, selects a budget-constrained subset of segments that maximises concept coverage and timeline coverage while penalising redundancy, abstractively summarises the result, and renders the selected segments into a single video with ffmpeg.

The system is built as a FastAPI backend with MongoDB for persistence and a React 18/Tailwind CSS frontend. Every model in the pipeline runs locally and is open-source rather than a paid third-party API: Whisper for transcription, Sentence-BERT (BAAI/bge-base-en-v1.5) for semantic embeddings, a distilled BART model (sshleifer/distilbart-cnn-12-6) for abstractive compression, and an optionally-enabled local Ollama model (llama3.2:3b) for concept extraction, with a deterministic TF-IDF keyphrase fallback used by default because the LLM path was measured to be too slow on CPU hardware for an interactive demo. Long-running merge jobs are tracked through a durable, MongoDB-backed job and task-queue system rather than an in-process thread: once the core pipeline publishes an immutable "evidence manifest" describing which segments were selected, two independent lease-based background workers — one for the highlight video, one for the written summary — claim and process that manifest, so a crashed worker or a server restart recovers the job exactly once instead of losing it or silently duplicating it.

The project also includes a source-rights and publication-gating layer that records, per source video, the basis under which it may be reused (user-owned, Creative Commons, explicit permission, public domain, or unknown), and gates whether a job's output is eligible for publication accordingly; a semantic search and conversational question-answering feature backed by a FAISS vector index over every transcript the platform has processed; and a shadow-mode acquisition-observability system that records, as an append-only, hash-chained event log, every download/metadata/caption read performed against a source video, without yet enforcing anything, as a foundation for future compliance auditing.

The selection pipeline was evaluated against a hand-authored gold standard of 103 important concepts across seven real YouTube videos spanning five genres (tutorials, a podcast, an interview, and technical lectures), using concept recall, concept precision, redundancy, and temporal-coverage metrics defined specifically for this problem rather than borrowed wholesale from text-summarisation literature such as ROUGE or BLEU, since the system's central claim is about which parts of the source were chosen, not only how the chosen text reads. A component-ablation study on held-out videos the scoring weights were never tuned against confirmed that the concept-extraction and coverage terms both contribute measurably to selection quality over a relevance-only baseline. The backend carries 548 automated tests across 57 test files covering the semantic segmenter, concept extractor, coverage selector, summarisation policy, fusion engine, the durable task queue and worker recovery logic, the rights and acquisition-observability services, and API-level security and language-capability gating. This document describes the requirements, design, implementation, evaluation, and testing of the system, and reflects honestly on what was measured, what had to be disabled by default for hardware reasons, and what remains open for future work.
